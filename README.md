# coco- 개발 스킬

Matt Pocock, Addy Osmani, Lauren Tan(pstack)의 개발 절차를 목적별로 통합한 스킬 모음입니다. 원본 122개 스킬과 Addy 명령 9개의 통합 위치를 추적하며, 통합 진입점 22개에 팀 전용 스킬 3개를 더한 총 25개 스킬을 제공합니다.

표시 이름과 폴더명은 **`coco-build`**, 실제 호출은 **`$coco-build`**입니다. 모든 통합 스킬이 같은 `coco-` 접두사를 사용합니다. pstack과 원본 팩은 설치·호출하지 않으며, 고정한 원문은 비활성 자료로 보관합니다.

## 사용

어떤 절차가 필요한지 애매하면 `$coco-start`와 작업을 전달합니다. 목적이 분명하면 해당 스킬을 직접 호출합니다.

스킬을 알아보고 싶으면 `$coco-tellmeskill`을 호출합니다. COCO·시스템·플러그인을 포함한 현재 사용 가능한 전체 목록을 보여주고, **스킬 선택 → 간단 설명/상세 설명 선택 → 원문 기반 설명** 순서로 진행합니다. 모든 스킬과 두 설명 모드에 [같은 양식](skills/coco-tellmeskill/references/explanation-format.md)을 적용하고 설명 분량만 바꿉니다. 설명할 스킬의 작업은 실행하지 않습니다.

`$coco-push`는 원격 `dev` 또는 `develop`의 최신 변경을 현재 작업 브랜치에 반영하고 충돌 해결·검증 후 해당 작업 브랜치를 일반 푸시합니다. 푸시 전에 실제 변경과 브랜치명의 작업요약을 비교하며, 요약이 부적절하면 브랜치명과 연결 Jira 태스크의 제목(Summary)·작업설명(Description)을 맞춥니다. 기존 요구사항·수용 조건은 보존하고 정리가 필요한데 티켓 갱신을 확인하지 못하면 푸시 전 멈춥니다. 적절한 이름·티켓은 유지하며 기존 원격 브랜치를 자동 삭제하지 않습니다. 두 개발 기준이 모두 있고 저장소 규칙으로 정할 수 없으면 선택을 받습니다. 기준 브랜치와 최종 푸시 목적지를 구분하며, 사용자 변경을 덮어쓰거나 강제 푸시하지 않습니다.

`$coco-updateskill`은 **전체 스킬 목록 → 수정할 스킬 선택 → 팀에 맞게 바꿀 내용 질문** 순서로 시작합니다. 목록에는 COCO·시스템·플러그인 스킬을 포함하고 각 선택·질문에서 답을 기다립니다. 대상과 수정 내용을 이미 알려줬다면 같은 질문을 반복하지 않습니다. 요구가 정해지면 공통 규칙·호출·출처의 영향을 정리한 뒤 수정·검증·커밋·설치 확인까지 진행합니다. 제안만 요청하면 파일을 변경하지 않으며, 외부 플러그인 캐시나 수정한 개인 설치 파일을 임의로 덮어쓰지 않습니다.

```text
$coco-clarify 주문 취소 기능의 범위와 아직 정하지 않은 동작을 확인해줘.
$coco-build 승인한 계획의 다음 작업 하나를 구현해줘.
$coco-build 합의한 계획을 연속 실행하고 작업별로 검증·커밋해줘.
$coco-review 이 작업의 미커밋 변경과 새 파일까지 포함해서 검토해줘.
$coco-verify 캐시 무효화 변경이 다른 소비자를 깨뜨리지 않는지 실행으로 확인해줘.
$coco-push origin/develop 기준으로 현재 브랜치를 최신화하고 검증 후 푸시해줘.
$coco-updateskill coco-build 우리 팀의 검증 명령과 리뷰 절차에 맞게 수정해줘.
```

작은 정적 수정은 수정과 필요한 확인으로 끝냅니다. 명확한 기능은 기존 합의에서 구현으로 진행하며, 명세·설계·전문 검토는 필요한 경우에 추가합니다. 경량·표준·강화라는 검증 수준과, 작업 하나·연속 실행이라는 진행 모드는 별개입니다.

`$coco-build`에서 새 기능 브랜치는 `종류(파트)/지라태스크번호-한글작업요약` 형식으로 만듭니다. 예를 들어 Jira 태스크 `TEAM-123`의 요약이 `OAuth2.0_구글`이고 종류·파트가 `feat`·`be`이면 `feat(be)/123-OAuth2.0_구글`입니다. 요약은 해당 태스크의 제목/Summary와 같게 사용하며, 정보가 없거나 Git이 허용하지 않는 문자가 있으면 필요한 내용만 확인합니다. 상세 기준은 [브랜치 준비 규칙](skills/coco-build/SKILL.md#기능-브랜치-준비)에 있습니다.

## 설치와 검증

Python 3.9 이상만 필요하며 런타임 외부 패키지는 없습니다. 저장소에서 실행합니다.

```sh
python3 scripts/validate.py
python3 -m unittest discover -s tests -v
python3 scripts/install.py --dry-run
python3 scripts/install.py
python3 scripts/validate.py --installed "$HOME/.codex/skills"
```

기본 설치 위치는 `~/.codex/skills`입니다. `--dest /원하는/스킬/폴더`로 다른 위치를 지정할 수 있습니다. 설치 대상 런타임이 스킬 형식을 지원해야 하며, 다른 제품의 API나 도구가 검증됐다는 의미는 아닙니다.

설치는 25개 스킬과 `_coco-shared`만 복사합니다. 기존 다른 스킬은 유지합니다. 같은 이름의 외부 스킬, 수정한 설치 파일, 추가한 개인 파일이나 심볼릭 링크와 충돌하면 먼저 중단합니다. 동일한 재설치는 변경하지 않으며, 이전 설치의 파일이 그대로인 경우에만 업데이트합니다. 스킬 목록 갱신 시점은 사용하는 에이전트가 결정하므로 새 대화나 스킬 새로고침이 필요할 수 있습니다.

## 통합 규칙과 원문

- [공통 계약](skills/_coco-shared/contracts.md): 입력·완료·검증 근거·커밋·재개·권한 경계.
- [충돌 해결 기록](skills/_coco-shared/decisions.md): 원본의 다른 규칙을 어떻게 선택했는지와 이유.
- [원본별 대응표](docs/source-index.md): 131개 원본 항목 각각의 통합 위치와 원문.
- [고정 원문과 체크섬](sources/manifest.json), [규칙별 대응 정보](sources/coverage.json).
- [동작 평가](docs/evaluation/README.md): 기존 절차의 연결 문제, 통합 후 시나리오와 검증 한계.
- [설계](docs/design.md), [작업 계획](docs/implementation-plan.md).

`build`가 제품 작업 수정·커밋·완료 처리를, `push`가 요청한 동기화의 통합 커밋과 원격 푸시를 맡습니다. `review`는 문제를, `verify`는 실행 근거를 반환합니다. 명세·상태의 기준 위치를 각각 정해 복제 체크리스트를 만들지 않습니다. 필수 검사가 실패했거나 실행되지 않았으면 완료로 표시하지 않습니다.

기능별 브랜치와 작업별 커밋을 사용합니다. 리뷰 범위에는 현재의 커밋·인덱스·작업 트리·새 파일을 포함합니다. 준비한 자동화와 실제 활성화, 출시 가능 판단과 실제 배포 성공은 각각 구분합니다. 스킬은 사용자의 권한 범위를 확대하지 않습니다.
