# coco-push

원격 `dev` 또는 `develop`의 최신 변경을 현재 작업 브랜치에 반영하고, 충돌 해결·검증 후 그 작업 브랜치를 일반 푸시한다. 최신 반영과 푸시는 [공통 계약](../_coco-shared/contracts.md) 및 [동기화 절차](references/sync-and-push.md)를 따른다.

## 진행

1. 저장소 최상위, 현재 브랜치·HEAD·상태, 진행 중인 Git 작업, 원격과 업스트림, 저장소 규칙과 검사 명령을 확인한다. 작업 브랜치를 유지하고 시작 커밋·변경 경로를 기록한다. 이 호출은 해당 범위의 동기화·충돌 해결·일반 푸시 요청으로 처리하며 같은 승인을 다시 요구하지 않는다. 설명·검토만 요청한 경우에는 실제 푸시하지 않는다.
2. 기준 원격과 `dev`/`develop`, 별도의 푸시 원격·브랜치를 확정한다. 명시한 대상, 저장소 지침·설정, 현재 PR의 기준 등 확인한 근거를 우선한다. 두 개발 브랜치가 모두 있고 기준을 결정할 근거가 없으면 둘 중 하나를 선택받는다. 둘 다 없으면 다른 기준을 임의로 택하지 않는다. 기본 푸시 대상은 현재 작업 브랜치와 같은 이름이며 기준 브랜치로 변경하지 않는다.
3. 사용자 미커밋 변경을 보존한다. 소유·범위가 확인된 요청 작업은 필요한 검증 후 작업별 커밋으로 준비한다. 소유를 알 수 없는 변경이나 기존 merge/rebase 등이 있으면 상태와 필요한 결정을 제시한다. 임의의 전체 커밋·stash·reset·clean으로 시작 상태를 지우지 않는다.
4. 원격의 실제 최신 ref를 조회·fetch하고 가져온 커밋을 고정한다. 푸시 대상에만 있는 커밋도 반영한다. 기본 pull 동작은 `fetch + merge`로 분리해 공유 이력을 유지한다. 충돌은 양쪽 의도·주변 코드·테스트를 읽고 파일별로 해결한다. 제품 동작 선택이 불분명하면 그 결정만 확인한다.
5. 미해결 인덱스, 충돌 표식 의심, 변경 diff를 확인하고 저장소의 필수 검사와 충돌 영향 검증을 수행한다. 해결 경로만 스테이징하고 필요한 통합 커밋을 완성한다. 자동 병합됐어도 의미 충돌을 검증한다. 필수 실패·미실행 또는 미완료 Git 작업이 있으면 푸시하지 않는다.
6. 푸시 직전 기준 ref가 전진했는지 다시 확인하고, 달라졌으면 다시 통합·검증한다. 검증한 HEAD를 확인한 단일 쓰기 목적지에 명시적인 단일 refspec으로 일반 푸시한다. 강제 푸시·미러·전체 브랜치 푸시나 보호 규칙 우회를 사용하지 않는다. 경합으로 거절되면 최신 변경을 다시 가져와 통합·검증한다. 갱신·통합 라운드와 총 push 시도는 각각 최대 3회로 제한한다. 인증·보호 정책·네트워크 장애는 경합으로 취급하지 않는다.
7. 성공 응답과 원격 ref를 다시 읽어 결과를 확인한다. 대상 원격 브랜치가 검증한 커밋과 일치해야 성공이며, 직후 다른 커밋으로 전진했다면 포함 관계를 확인하고 관찰 상태를 구분한다. 검증 이후 로컬 변경이 생기면 해당 HEAD를 푸시 성공으로 포장하지 않는다.

## 결과

기준 원격/브랜치와 가져온 커밋, 작업·푸시 대상 브랜치, 해결한 충돌과 판단, 생성한 커밋, 검사 결과, 푸시한 커밋과 원격 확인, 남은 사용자 변경이나 차단 사유를 보고한다. 충돌이 없었다는 것은 이번에 확인한 범위·시점의 결과이며 향후 경합까지 보장하지 않는다.

`coco-push`는 통합 커밋과 해당 브랜치 푸시를 맡는다. 새 기능이나 무관한 수정은 `coco-build`의 별도 작업으로 남기며 제품 작업의 완료 상태를 임의로 갱신하지 않는다. PR 생성·병합·배포는 이 요청에 포함하지 않는다.

예: `$coco-push` 또는 `$coco-push origin/develop 기준으로 현재 브랜치를 최신화하고 충돌 해결과 검증 후 푸시해줘`.
