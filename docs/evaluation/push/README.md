# 개발 기준 반영과 푸시 확인

사용자가 요청한 `coco-push`는 원격 `dev` 또는 `develop`의 최신 커밋을 현재 작업 브랜치에 반영하고, 충돌 해결·검증 후 단일 원격 브랜치에 일반 푸시합니다. 개발 기준과 쓰기 목적지를 구분하고 검증한 OID를 게시합니다. 코드 충돌 때문에 추가된 통합 커밋은 push가 소유하며 제품 작업의 완료 상태는 바꾸지 않습니다.

[적용 보고서](report.md), [상태·결과](results.json), [명령 기록 358개](commands.jsonl)는 새 컨텍스트 한 에이전트가 작성·적용한 다섯 로컬 fixture의 원본 기록입니다.

| 사례 | 실제 결과 |
|---|---|
| develop만 존재하고 기능 브랜치의 업스트림이 develop인 상태 | 텍스트 충돌 해결 후 검사 3개 통과. 기능 브랜치에 게시하고 원격 OID 확인. develop은 변경하지 않음 |
| 검증 뒤 다른 클라이언트가 기능 브랜치에 먼저 푸시 | 실제 첫 푸시 거절(exit 1)을 확인. 상대 커밋 통합·검사 4개 통과 후 두 번째 일반 푸시 성공 |
| dev와 develop이 모두 있고 기준 결정 근거가 없음 | 선택 필요 상태로 종료. HEAD·파일·원격 ref 유지 |
| 소유를 알 수 없는 사용자 수정이 존재 | 임의 커밋·stash·reset 없이 원래 내용과 상태 유지 |
| 충돌 해결 후 필수 검사 실패 | 게시하지 않음. 해결한 스테이지와 MERGE_HEAD를 복구 가능한 상태로 보존 |

작성자의 [별도 읽기 확인](parent-readback.json)으로 성공 사례의 실제 원격 OID·개발 커밋 및 상대 커밋의 포함 관계, 중단 사례의 상태, 읽은 스킬의 현재 해시를 확인했습니다. 이는 Git 상태의 재조회이며 새 모델 실험이나 실제 서비스 테스트는 아닙니다.

[실제 설치 확인](installation.json): 총 24개 스킬/78개 파일이 저장소와 바이트 일치하고, 기존 다른 스킬 항목 50개를 보존했습니다. 같은 재설치는 `unchanged`였습니다. 기존 자동 테스트 23개, 새 스킬 형식 검사와 패키지 참조 검사가 통과했습니다.

모든 테스트 원격은 임시 로컬 bare 저장소입니다. 사용자 저장소의 원격 푸시·서비스 보호 정책·인증·여러 push URL·네트워크 응답 유실·모든 충돌 종류를 검증한 것은 아닙니다. 같은 에이전트가 fixture와 기대 조건을 작성한 제한된 적용이며, 반복 시험이나 일반적인 안전 보증을 주장하지 않습니다.

원문과 명령 기록의 `/tmp/…` 또는 `/private/tmp/…`는 당시 경로입니다. `export.json`은 보존 파일의 해시를, `git-history/index.json`과 bundle은 작업 저장소·로컬 원격 이력을 기록합니다. 중첩 `.git`이나 bare 내부를 그대로 복사하지 않았습니다. 테스트 소스와 기록은 설치 대상에 포함하지 않습니다.
