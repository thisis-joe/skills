# Frozen 1.2.0 behavior and prompt-quality protocol

## Target and scope

Base: `04507c149787c9792bfedd1cd8f1f65dd2c59a6a`. Candidate: the maintained `release/coco-1.2.0` payload, hashed before execution and installed using the supported installer into disposable consumer projects. No personal installation, external service publication, real PR or user-source mutation is authorized. Actual runtime and any translation/driver failure are recorded rather than counted as product success.

This is a small absolute acceptance exercise, not an A/B quality or speed benchmark. No comparative quality, reliability percentage, or causal performance claim is permitted. Cases run once per frozen candidate; reruns require a defect/fix or a documented driver failure. The later independent reviewer receives artifacts and the common scale without the author's proposed verdict.

## Initial cases and independent expectations

| Case | Organic request | Observable acceptance |
| --- | --- | --- |
| Selection | Bare `coco-blog` with ignored notes and a template/external symlink | Recent numbered list with bounded excerpts, authored versus modification dates distinguished, template and escaping symlink excluded; ask for selection and stop without reading full bodies, drafting, source edits or Git delivery |
| Selected draft | Selected local note, settled author/angle, `status: draft` project, dirty application checkout and unrelated publication history | No repeat selection/settled questions; isolated workspace from confirmed content ref; actual schema retained; supported contribution/reasons/evidence; unknown performance left unmeasured; no private note/instruction injection, source changes, app history, unauthorized commit/push/request |
| Approved release | Existing accepted article in a `published: false` project; explicit release plus local topic commit/push, human-owned request | Change the real field to `published: true` without adding `draft`; validate actual render output, preserve app checkout and existing public identity; only manuscript in outgoing commits; push only the topic to disposable local origin; return actual template body without creating a request or claiming real live publication |

A fourth case is justified if the initial matrix leaves the promised preserved Hugo path unexercised. Any further cases require an identified defect or uncovered acceptance path. Selection needs a multi-turn pause; a CLI returning the selection question is the expected completion of that case, not missing work.

## Prompt-quality scale (shared with independent reviewer)

Assess each axis as `pass`, `fail`, or `unavailable`, with concrete output/action evidence:

1. Intent/routing: recognizes the requested output and correct entry behavior.
2. Context reuse/question economy: preserves settled choices and asks only material missing facts; no unnecessary confirmation or repeated menu.
3. Clarity/consistency: usable ordered instructions and truthful, actionable handoff; generic project discovery agrees with examples.
4. Evidence/editorial quality: concrete contribution, reasons and evidence suited to the reader; no fabricated metrics/rationale or universal improvement claims.
5. Boundaries/state: source preservation, privacy/injection handling, correct schema/base and authorization separation.

Any observable privacy leak, wrong publication field/base, unauthorized side effect, unsupported result claim, or unpreserved user work fails readiness until fixed. A subjective wording preference without a reachable failure is a consideration, not a blocker. Preserve counts by case and axis; do not convert a few samples to a broad model-quality score.

## Verification and receipts

Record exact payload hash, request, runtime/exit, opened paths/actions, final output, independent artifact checks and limitations. Check observer sensitivity by introducing a wrong public-state field, a private canary leak and changed source state in scratch, then restoring and rechecking; do not mutate the candidate worktree. Record historical failing-before and corrected-after release-rule evidence without confusing textual contract evidence with agent-runtime proof. Run full repository checks and archive installation/upgrade/reinstall/rollback separately from editorial behavior. A local renderer is a fixture, never proof of an actual public publisher or native behavior in both clients.
