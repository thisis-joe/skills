## Contradictions, gaps and boundary caveat

No concrete contradiction between the selected conditional outputs and the requested artifact-only boundaries was found in these cases. The evidence does expose execution gaps: command-guard/pre-commit procedures ask for real runtime smoke tests, but the required runtime/dependencies were unavailable and installs were not authorized. Those steps remain unavailable; a local stand-in or missing-tool failure does not convert them to passed. The two quality owners remain separate and the audit does not rewrite the bar.

One early case-2 `npm run typecheck` invocation used npm's default cache/log settings before subsequent commands redirected npm state into this temporary root. Ordinary npm diagnostic cache/log writes outside `/tmp/lets-conditional-validation` are therefore possible. Their presence was not inspected or removed, so strict “all incidental writes were confined to /tmp” is **not proven**. No global configuration mutation was requested or deliberately performed. This caveat is an evaluation-side boundary lapse, not evidence of an installed LET’S policy defect.

Evidence existence/hashes are checked in evidence-integrity.json; that integrity check is not a behavioral pass. These results support concrete conditional-mode application in this bounded local setting, with no claim of independent repetition, full platform integration, complete shell parsing, statistical reliability, or personal-install approval.
