# Frozen comparative protocol

Accepted before candidate executions. Requirements: [spec](../../specs/staged-development.md).

## Conditions and isolation

Use candidate active skill files, the published npm `@thisis-joe/coco-skills@0.2.0`
tarball (registry gitHead `256c88073a1bfa858c6221197959d6ad1d7d8a5c`, SHA-512
`hD0WIpwClXm9ODj/2Q63bp3lOgEMcC/dy73MwuVAYFaHJvI7P0Cjsjgr7E7gi6sv9CJandGFoQyALza7SEGWWg==`),
and no loaded skill bodies. Each project has the same seed, brief, capabilities
and project rules. The CSV project deliberately has no AGENTS/setup/tracker.
Random project directories and copied local `.guide/` files avoid variant labels
and grading cues. Keep scorer/variant mapping outside project directories.

Run one independent native Codex context per project. Do not reuse the author's
conversation or reasoning. Retain actual JSONL tool/action events, final answers,
synthetic owner replies, sources, file hashes, Git history and outcome probes.
Native defaults are shared across conditions; do not hardcode different models.
Record CLI version, ordering, failures and repairs. Existing catalog metadata
may remain discoverable; forbid personal/global skill-body reads and audit them.
No global settings, external services, publication or spawned nested agents.

## Six matched tasks

1. Static HTML copy edit: preserve adjacent content, avoid ceremonial documents.
2. Small CSV CLI addition: JSON mode, preserved default, empty and malformed input.
3. Pagination regression: real traversal, boundary conditions and useful errors.
4. SQLite ledger: restart persistence, idempotency, conflicting reuse and order.
5. Local HTTP sum endpoint: actual requests, auth/input/size/error boundaries.
6. UI interaction with no configured browser: implement what can be checked and
   accurately leave required browser verification pending. HTML parsing is not
   substituted for actual browser proof.

Each arm has six matched scenarios, not six repetitions of an identical task.
Report cases individually. The sample supports bounded observations; do not
claim population quality rates, noninferiority or speedups. A speed claim would
need at least five repeated alternating samples per task/side and limiter work.

## Owner replies and learning

Candidates first receive the organic brief. When a question or handoff prevents
completion, resume with a retained scripted owner response: accept shown defaults
within the brief, opt into automatic basic steps for this spec, use descriptive
branching without Jira, and decline separately introduced specialists while
retaining ordinary checks. These are synthetic decisions, never real user
behavior. An experienced profile is the explicit opt-in follow-up; the first turn
is a cold/manual profile. Do not interpret later turns as independent repeated
samples. A reviewer or missing runtime gap is not secretly answered with a pass.

## Outcome and process are separate

`scenarios.py` checks public CLI, persisted SQLite and real localhost HTTP outputs
with independently specified values. No-skills is not penalized in functional
correctness for omitting COCO documents, skill introductions or TDD.
Record process dimensions separately: saved spec/plan, observed red/green,
implementation commits, review status, declined-specialist handling, user work
preservation and no publication. Classify prompts as learning/selection,
material decisions, redundant fact questions or execution barriers, with evidence.

Report wall time and model usage as descriptive execution costs; human active
time/comprehension are unmeasured. Keep first-use, opt-in and blocked verification
observations distinct. An independent reviewer receives sanitized artifacts and
the shared outcome rubric without condition labels or expected winners. Inject
at least one bad output and one missing-runtime false-completion claim in scratch
to show the observers can detect failures. Preserve initial failures and targeted
reruns separately; never rewrite raw trials after a candidate repair.

Produce separate candidate-versus-0.2.0 and candidate-versus-no-skills verdicts,
including inconclusive or unfavorable findings. Passing a package validator or
this scorer does not certify skill compliance, all models, or real user ease.
