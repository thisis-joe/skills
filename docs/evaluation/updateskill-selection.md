# coco-updateskill 시작 대화 점검

이번 변경은 대상과 수정 목적을 한 단계에서 확인하던 시작 절차를 **전체 목록 → 대상 선택 대기 → 수정 내용 질문 대기**로 분리한다. 기존 팀 유지보수·출처·설치 절차는 유지한다.

## 대화 흐름 검토

작성자가 다음 입력을 수정한 지침에 대입해 단계와 부수 효과를 검토했다. 새 에이전트나 실제 앱 UI에서 실행한 대화 시험은 아니다.

검토용 카탈로그는 `coco-build`, `coco-updateskill`, `sample:build`, `skill-creator` 네 항목이다. COCO 외 항목과 자기 자신도 포함하고, 이름순 번호를 다음 턴에도 유지한다.

| 사용자 입력과 현재 단계 | 다음 응답·행동 |
|---|---|
| `$coco-updateskill` | 네 항목 모두 번호·정확한 식별자·한 줄 용도로 표시하고 수정할 스킬 하나를 선택받는다. 수정 내용은 아직 묻지 않고 대기한다. |
| 위 목록에서 `2` 선택 | `coco-updateskill`을 선택했다고 확인하고 팀에 맞게 어떤 내용을 바꿀지 묻는다. 수정·커밋·설치 없이 답을 기다린다. |
| 대상 선택 단계에서 `99` 입력 | 유효한 대상을 다시 선택받는다. 번호를 재배정하거나 임의의 스킬로 진행하지 않는다. |
| `$coco-updateskill coco-build` | 이미 알려준 대상을 재선택받지 않고 수정할 내용을 묻는다. |
| `$coco-updateskill coco-build 이 저장소에서 검증 명령은 pnpm test로 바꿔줘` | 주어진 대상·요구·프로젝트 범위를 재질문하지 않고 실제 원본과 적용 조건을 확인한다. 다른 저장소의 공통 명령까지 바꾸지 않는다. |
| 대기 중 `취소` | 수정 없이 종료한다. |

동명 스킬은 네임스페이스를 유지해 선택하고, 카탈로그를 조회할 수 없으면 확인 가능한 범위를 밝히도록 했다. 유지보수 UI의 기본 요청도 같은 단계로 맞췄다. 목록을 만드는 동안 모든 원문을 읽거나 선택한 스킬의 작업을 실행하지 않는다.

## 실행한 검사

- `python3 scripts/validate.py`: 25개 스킬, 고정 원문 체크섬·대응표·참조 통과.
- `python3 -m unittest discover -s tests -v`: 실제 임시 파일·Git 저장소를 사용하는 기존 23개 검사 통과.
- 공식 `skill-creator/scripts/quick_validate.py skills/coco-updateskill`: 통과.
- `git diff --check`: 통과.

자동 검사는 패키지·설치·리뷰 범위의 기존 불변 조건을 검사한다. 대화 단계 검토를 실제 사용자 응답 대기, 전체 런타임 카탈로그 출력, 모든 모델의 준수에 대한 실행 증거로 확대하지 않는다. 기존 [팀 유지보수 평가](updateskill/README.md)의 입력·출력·해시는 당시 기록으로 보존한다.
