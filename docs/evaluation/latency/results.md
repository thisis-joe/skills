# 1차 조정 동작 확인과 재측정 결과

[실험 조건](protocol.md)대로 조정 전(`main`, e643d83)과 조정 후(`feat/skill-latency-wave-1`) 스킬 사본을 같은 예제에 짝지어 실행했습니다. 2026-10-22 결과입니다.

## 실행 방식과 한계

- 이 Mac에는 `claude` CLI가 없어 설정 폴더 격리를 쓰지 못했습니다. 각 에이전트는 Skill 도구 없이 고정한 스킬 사본(`git archive`)의 `SKILL.md`를 경로로 따라가는 "경로 실행"입니다.
- 조정 후 사본은 두 시점입니다. B1~B5b, B7, B8은 97c3fd9, B6과 B5 재실행은 P2 문서 변경을 포함한 394f308입니다.
- 사례마다 1회 실행입니다. 다른 기록에서 단일 API 지연이 31~36초 나온 적이 있어, 10~20% 차이는 오차 범위로 봅니다.
- 시간은 에이전트 기록의 첫 행부터 마지막 행까지입니다. 예제 생성 명령과 최종 응답 작성이 포함됩니다.
- 판정은 실행 폴더, Git 상태, 모의 forge 호출 기록을 직접 확인한 새 문맥 에이전트가 했습니다.

- docs와 review는 이번 조정이 겨냥한 부분(큰 재작성, 범위 수집 명령)이 이 사례에서 크게 쓰이지 않아 차이가 오차 범위 안입니다.
- updateskill 문구 수정은 조정 전에도 무거운 평가를 돌리지 않아 시간이 같습니다. 등급 규칙이 시간을 줄이는 대상인 절차 변경(실제 기록 639~1,252초)은 이번에 확인하지 못했습니다.

## Windows에서 발견한 기존 버그

B9용 CI를 Windows에서 처음 돌리면서, 조정과 무관하게 이미 있던 문제가 드러나 함께 고쳤습니다.

- `scripts/validate.py`와 설치기가 Windows 기본 인코딩(cp1252)으로 UTF-8 파일을 읽어 시작하자마자 멈춤.
- merge 사전 점검, 최근 스킬 목록, 노트 검사 도구가 한글 출력에서 멈춤.
- 설치기가 입력 없는 실행(NUL)을 터미널로 오인해 설치 위치를 묻다가 취소됨.
- 노트 검사기가 `\` 경로로 출력해 INDEX.md의 `/` 표기와 맞지 않음.
- CRLF 체크아웃에서 스킬 파일의 절 구분과 해시 비교가 깨짐(`skills/** text eol=lf`로 고정).

## 결론

- 안전 조건을 잃은 사례는 없습니다.
- 경로를 정하는 일(start)과 배포가 아닌 출시 점검(ship)에서 시간이 30~40% 줄었습니다. push는 16% 줄었고, docs, review, updateskill 문구 수정은 차이가 없습니다.
- 보고 형식은 판정 에이전트들이 조정 후 쪽을 더 간결하다고 평가했습니다.
- 과제당 3회 반복과 판정 순서를 바꾼 재판정은 후속 분석에서 합니다.
