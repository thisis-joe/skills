# 실제 작업요약과 브랜치·Jira 정리 평가

현재 `coco-push`와 필요한 연결 자료를 새 컨텍스트의 에이전트 하나가 읽고, 직접 구성한 로컬 자료 5개에 적용했다. [원문 보고서](REPORT.md), [집계 결과](result.json), 각 사례의 명령·판단·티켓 전후 기록을 보존한다.

실제 임시 Git 저장소·bare 원격에서 2개는 일반 푸시·원격 OID 확인까지 완료했고, Jira 쓰기 거절·동일 번호의 프로젝트 모호성·다른 태스크의 이름 충돌 3개는 푸시 전에 멈췄다. 이름 변경 사례에서는 옛 원격 브랜치에만 있던 동료 커밋을 먼저 통합했고, 기존 Jira 설명·미완료 수용 범위·옛 원격 ref를 보존했다. 이름이 적절한 사례는 티켓 쓰기 없이 게시했다.

Jira는 파일 기반 **모의 어댑터**다. 실제 서비스 권한·인증·ADF 서식·동시 갱신은 시험하지 않았다. 모든 병합은 자동 병합이었고 필수 fixture 검사는 통과했다. 기존 텍스트 충돌·재시도 평가를 대체하거나 모든 모델에서의 준수를 보장하는 결과가 아니다.

읽은 스킬 파일 5개의 시작·종료 해시는 같았다. 부모 에이전트도 실제 HEAD·브랜치·원격 ref·티켓 파일과 보고서를 대조하고 Git bundle 10개를 확인했다. [부모 재확인](parent-readback.json)과 [원문 내보내기 체크섬](export.json)을 함께 둔다. 절대 임시 경로는 당시 실행 위치이며 같은 상대 경로의 파일과 Git bundle을 여기 보존했다. `.git`·bare object 폴더·Python 캐시는 복사하지 않았다.

초기 fixture 구성 수정 기록과 macOS `/var`·`/private/var` 경로 별칭 때문에 발생한 평가 수집기의 오판 기록을 삭제하지 않았다. 경로 비교를 고쳐 근거만 다시 수집했으며 Git 푸시·티켓 쓰기를 반복한 것은 아니다. 재현 방법과 제한은 원문 보고서에 있다. 보존 폴더 위에서 fixture 생성기를 다시 실행하지 않는다.

패키지 형식·참조·고정 원문 검사, 기존 자동 검사 23개, 공식 스킬 형식 검사와 설치 사전 검사가 통과했다. [루트 검사 기록](root-checks.json)은 실제 스킬 동작 평가와 별도로 읽는다.
