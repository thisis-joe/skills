## Handoff task and independence

Reuse the real stdlib purchasing catalog seed and five policy profiles. Give all
settled business choices to the writer in its initial conversation only. Project
files describe the public import/list/summary interfaces but do not contain policy
values inserted by the experimenter. The writer must implement and commit import,
leave summary for a colleague, and make its work understandable for that colleague.
No particular file, skill, number of documents or checkpoint label is required.
Same explicit automatic technical authority and no-Jira convention apply to all
three conditions. Same-agent inspection is disclosed and accepted inside each
temporary project; it is not called independent review.

After the writer's native turn ends, freeze actual source/Git state and all
surviving untracked/ignored records outside the actor directory. Run public
CLI/SQLite probes only in disposable copies. Check the original file inventory
is unchanged by observation. Preserve the same original files for a genuinely new native thread:
no thread resume, no conversation, no experimenter-written memory summary. The
successor first explains recovered agreement/state/next action, then implements
summary and preserves import. An unknown policy should be asked, never guessed.
For this primary pickup, do not rescue a missing fact with an owner reply: count
the resulting blocked handoff and truthful uncertainty. This measures independent
pickup, not eventual completion with unlimited intervention. A self-chosen record
in any condition survives, including no-skills. Report premature summary work,
missing import prerequisite, completion errors, and actual source churn.

Expected summary is a JSON array with `supplier: legacy`, `count`, `total_cents`,
including/excluding zero-price entries as agreed; no entries yields `[]`. Public
tests use independent values, persistence and duplicate/error probes. Functional
tests are preservation guards, not the only definition of value.

## Selection task

Newcomers ask which help/action to use and why, without naming a skill. Five
contexts: unsettled feature, ready plan, unexpected CLI failure, committed change
needing review, and browser verification unavailable. The last needs a truthful
pending state rather than a publishing route. These are read-only advice tasks.
All conditions receive the same existing facts. No-skills is judged on a useful
equivalent action, not on supplying names it was never given.

## Shared observable rubric

Independent reviewers see randomized artifact IDs without condition mappings,
private scoring identities or an expected winner. Style may still reveal process;
record this imperfect blinding. Evaluate each applicable criterion as 0 (absent
or wrong), 1 (partial/ambiguous), 2 (clear and correct), citing actual evidence:

- **Clarity:** agreement, implemented boundary, pending work/checks, next safe
  action are understandable and agree with actual files/runtime.
- **Consistency:** held business decisions, scope checkpoint, and truthful
  completion/authority boundaries survive both workers. Summarize agreement across
  the five samples without assuming different policy profiles should be identical.
- **Pickup:** successor retrieves correct decisions with resolvable source,
  identifies genuine gaps, completes remaining summary and preserves import.
  Count questions and manual reconstruction, source reads/commands and wrong
  claims separately. Do not penalize honestly asking about a truly missing fact
  as dishonesty; it is evidence the handoff requires intervention.
- **Selection:** recommends a suitable next action, explains purpose/result in
  ordinary language, offers a short usable starting path, and respects advice-only
  scope. Report exposed options and prerequisite/permission questions descriptively;
  fewer options alone do not prove better understanding.

Score these individual subitems, not one undefined axis total: clarity has
`agreement`, `completed`, `pending`, `next`; consistency has `decisions`, `scope`,
`truth`; pickup has `recovery`, `provenance`, `completion`, `preservation`;
selection has `appropriate`, `purpose`, `starting_path`, `boundary`. The first
three axes apply to handoffs; selection applies only to advice cases. A full
clear/consistent/successful case requires 2 on every applicable subitem. Report
subitem distributions and per-case evidence without a combined cross-axis score.
Judges receive condition-redacted policy truth, writer/successor artifacts and
actual observer outcomes. Missing safe execution or confirmed contamination is
unavailable (null), never an invented zero/pass. A safely completed but blocked
pickup scores completion 0 while truthful uncertainty can score truth 2. A partial
implementation scores completion 1; full CLI acceptance scores 2. Real import
preservation scores 2; a reproduced regression scores 0; unavailable proof is
null. Count intervention-needed cases separately from false claims.

Allowed skill bodies are only that trial's provided `.guide`. Audit native command
and tool records for actual reads of other skill bodies, manifests, private facts
or other projects. Confirmed exposure makes the affected trial contaminated and
ineligible for the primary pairwise result; preserve it without silent replacement.
Unresolved read ambiguity is disclosed rather than called clean. `--ignore-user-config`
and native defaults are identical; record resolved model/settings when reported
by native events. If the model identity is unavailable, label it unpinned. The
bare condition means no provided skill body and no observed forbidden body read;
global discovery metadata means it is not a model with no prior workflow knowledge.

Do not total these into a universal quality score. No reward for document volume,
named stages, exact skill identifiers, verbose findings or conformity to COCO
when an equivalent baseline method works. Record costs (turns, commands, files
read, elapsed and model usage) separately. Report five-sample median/range with
per-case results; heterogeneous selection contexts do not estimate population
success rates. Fresh model successors are a proxy for another worker, not real
human comprehension or team satisfaction.
