# coco-docs·coco-learn 분리 적용 기록

기존 `coco-document`를 공식 프로젝트 문서용 [coco-docs](../../../skills/coco-docs/SKILL.md)와 개인 학습용 [coco-learn](../../../skills/coco-learn/SKILL.md)으로 나눴다. 학습 노트는 작업 공간의 `TEMPLATE.md`가 정한 다섯 칸(핵심·예시·함정·셀프 체크·관련)과 본문 60줄 한도를 따르고, 함께 설치되는 [검사 도구](../../../skills/coco-learn/tools/check_notes.py)가 양식·분량·색인을 확인한다. 고정 원문은 바꾸지 않았고 원본 대응의 `family`와 `implemented_references`만 옮겼다.

## 대상과 방법

- 2026-10-20, 기능 브랜치 `feat/coco-docs-learn`, 기준 `main` `256c880`. A·B·C 평가 시점 스킬 커밋은 `2f95da8`이다. A·B·C 진행 중 검사 도구의 제목 끝 `#` 해석을 고쳤으나 세 시나리오의 제목에는 해당 문자가 없었다.
- 작성자 대화를 상속하지 않은 에이전트 4개가 대상 스킬의 `SKILL.md`와 그 링크 문서만 읽고 수행했다. 평가 기록·테스트·Git 이력은 읽지 않게 했다. 각 에이전트에 3~4턴의 사용자 입력을 미리 주고 전체 응답 기록을 받았다.
- 대상 자료: 이 저장소의 `scripts/install.py`(읽기 전용), 합성한 React 학습 노트 1개(본문 66줄, 검사 위반 5건, 사용자 메모 포함), 문서 평가용 저장소 clone.
- 판정: 작성자가 산출물에 검사 도구를 다시 실행하고 줄 수와 응답 기록을 직접 확인했다.
- 한계: 사용자 입력을 한 번에 전달했으므로 턴마다 응답을 받고 다음 입력을 주는 방식보다 독립성이 약하다. 실제 클라이언트 대화가 아니다. 평가 산출물(노트·how-to 문서)은 저장소에 반영하지 않았다.

## 평가 후 보완

- `coco-learn`: 다른 개념을 "추가"해 달라고 하면 링크된 새 노트로 나누고 한 줄로 알린다. 부분 정답은 상태를 유지하고 빠진 부분을 묻는다. "다시 볼 것" 같은 개인 메모는 `review` 상태와 함정·셀프 체크로 옮기고, 지운 문장은 응답에 모두 적는다. 한도는 목표가 아닌 상한이다. 위치 기록 제안은 처음 정할 때 한 번만 한다.
- `coco-docs`와 `coco-learn`의 경계: 상대 스킬의 요청이면 한 줄로 알리고 그 스킬 절차로 이어간다. 안내만 하고 멈추지 않는다.
- 문서 점검: 쓰기 명령은 일회용 임시 대상에서만 실행한다.

## 보완 후 재평가 D

B와 같은 시드 노트를 새로 복사해, 보완한 `coco-learn` 규칙으로 3턴을 수행했다. 경계·응답 길이 보완은 D 이후에 추가했으므로 행동 평가하지 않았다.

- D1 정리: 노트 5개(마지막 1개는 D2)로 나눴고 본문은 27~47줄이다. 핵심은 노트당 2~3개였다. B에서 대부분 칸을 한도까지 채우던 경향이 줄었다. 지운 문장 4개를 응답에 원문으로 적었다. 면접 메모는 `strictmode-double-effect.md`의 `status: review`와 셀프 체크 질문이 됐고, 검사 도구의 다시 읽을 순서 첫 번째로 올라갔다. 검사 exit 0.
- D2 cleanup 노트에 AbortController 예시 추가: 예시 칸은 사례 하나라는 규칙 때문에 링크된 새 노트 `effect-fetch-abort.md`를 만들고 그 이유를 한 줄로 밝혔다.
- D3 의존성 배열 설명: 배열에 넣어야 할 값이 빠졌다고 짚고 `learning`을 유지했다.

남은 판단: 같은 개념의 예시를 하나 더 원할 때 새 노트로 나누는 것이 최선인지는 사용자 피드백으로 다시 정할 일이다. 개인 스킬 폴더(`~/.claude/skills` 등)의 설치본은 갱신하지 않았으므로, 다시 설치하기 전까지 세션 목록에는 이전 `coco-document`가 보인다.
