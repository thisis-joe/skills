## Independent fairness review

A separate agent reviewed the protocol and root-owned runner read-only. Its
findings changed the harness before exposure, rather than changing scores after
seeing a favored outcome:

- Equal initial authorization replaces the former handoff-dependent blanket
  permission. Private fact replies follow actual questions; public requirement
  re-questions also receive truthful phase-appropriate answers.
- Resolve a real pending product question before treating provisional runnable
  code as a quality correction. Only relevant failed expectations reveal private
  facts; a summary error does not disclose collision or malformed-row choices.
- A changed-phase duplicate answer preserves within-file policy but replaces
  the old stored-row policy, matching the explicit scope change.
- Committed checkpoints accept implementations split across modules and reject
  uncommitted product Python. Public CLI behavior, not a COCO document, triggers
  the checkpoint. Unexecuted summary evidence is unknown, not pending-work proof.
- Classified questions are retained separately from messages actually delivered.
  Delivery requires a real process and native thread-start event. Public topics
  never count as newly elicited private business choices.
- A snapshot/outcome variable alias could have crashed lifecycle recording; a
  success-path regression now exercises initial, changed and resumed orchestration
  through result persistence. No primary trial hit that defect.
- Timed-out/uncertain predecessors are quarantined. No fresh actor, immutable
  product snapshot, or passed outcome is claimed from an unstable project.
  Read-only review source/HEAD are compared against the prepared patch afterward.
