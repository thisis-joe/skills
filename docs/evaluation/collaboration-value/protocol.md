# Frozen collaboration comparison protocol

Source candidate: active skills at `622975e`, copied by tracked Git blobs rather
than an installed/global cache. Final protocol/fixtures/driver revision and hashes
are recorded in control.json before primary execution. No upstream tree runs.
The [scope](../../specs/collaboration-value.md) defines outcomes and reduction gates.

## Matched projects and shared capabilities

Run five independent paired inventory lifecycles and five independent paired
read-only review projects. Same seed/profile and source in each pair; alternate
which condition runs first for successive seeds. At most two pairs execute at
once. Subsequent turns/stages are not new independent samples. Report median,
range and every pair rather than treating stages as repeated independent trials.

Initial AUTH is byte-identical in both arms. It grants automatic basic technical
execution for this feature, not product decisions; accepts disclosed same-agent
inspection inside the inventory session, declines separate specialist examinations,
and grants local commits but no publication. This is an explicit-automatic profile,
not a claim about cold manual onboarding or the full multi-model upstream harness.
Only `.guide/` contents differ. Same native default model/settings and tools; no
model override, personal/global body loading, nested agents, packages or services.
Do not give the arm that asks a question extra blanket permission or defaults.

## Owner, milestones and budgets

Five private profiles vary SKU canonicalization, duplicate collision, malformed
row handling and summary inclusion of zero-price items. The owner sees only the
latest final question, previous fact-topic labels and the common business domain;
no condition label or expected winner. A native semantic classifier identifies
actual question topics. The driver answers from exact frozen fact strings for
those topics. Open-ended requirements questions may elicit all four facts. It
never invents a default or releases facts merely because code guessed at them.
Questions about public command/grouping/batch requirements receive the relevant
phase-appropriate contract, including after lost context; the owner is not made
artificially unable to recall its own requirements. These re-questions are kept
separate from first-time private business choices. Actual pending questions are
answered before judging a provisional implementation as needing correction.
Scheduled trial-result questions are classified as checkpoint feedback, with no
policy topics. Once the objective slice is ready, they advance the fixed trial
schedule rather than creating an extra factual-answer turn.
Retain classifier raw actions, validate its schema and audit revealed facts.
One classifier retry is allowed for infrastructure/format error in either arm,
with the first attempt retained; it is not an additional actor turn.

Each phase allows at most four actual owner-answer messages (and therefore up
to five actor turns), plus one correction/repair opportunity after an observable
wrong result. No-question early stops receive at most one fixed continuation,
without any new business facts, within that same answer cap. Missing prerequisites
or exhausted budget remain failed/pending, never silently rescued. Every actor
invocation is capped at 420s; inventory actor elapsed budget is 1800s across its
lifecycle. Classifier calls have 90s caps. Review has one actor call, capped at
420s. Its complete read-only contract requires no owner decision: classify any
questions for observation, but do not turn an optional fix offer into another
review. Missing or provisional findings remain observable. Owner/grading cost is
recorded separately.

Milestone 1 is a real successful unique-row import and public list readback.
Before advancing, actual hidden outcome probes test the chosen business rules.
If unmet, the same one bounded correction opportunity supplies relevant concrete
expected behavior and the observed failing check labels. The initial failed
outcome remains. Merely asking questions, writing a spec or saying pending cannot
advance the event schedule. A ready checkpoint is not full task completion.

The fixed scope-change message arrives at that common runnable first slice. It
adds supplier identity, migration and batch replay behavior, preserving explicitly
named prior choices. Both arms must commit this runnable import/storage slice
before remaining summary. The observer watches a new commit touching product
Python (including modules behind a stable CLI wrapper), committed Python state
matching working files, and actual changed-import CLI readback. The primary
comparison uses the requested planned work checkpoint and ends the native turn
before dropping its conversation. A pre-primary host probe sent SIGTERM but
could not establish tool-child cancellation (group-status EPERM; child continued).
Do not run a fresh actor concurrently with that uncertain predecessor. Abrupt
process interruption is unavailable here and is not a primary passing claim.
Retain the failed capability probe and the pre-run protocol amendment.

The next actor uses a **new native thread**, no old thread ID, no transcript and
no experimenter memory packet. It sees the surviving project and generic RESUME
instruction. Summary must respect the real earlier decisions. Whether the stop
was a planned checkpoint or too late (summary already complete) is explicit; late
capture cannot count as proof of resuming pending work. The task's own created
documents survive in both conditions. The driver does not delete bare documents
or write COCO's missing ones. Real CLI/SQLite acceptance checks run before and
after a single bounded correction opportunity.

## Intervention, rework and quality

The decision count is distinct factual choices requested, not a reward for fewer
question marks. Retain exact questions/answers, topics newly disclosed versus
already disclosed, procedural consent requests and scheduled events. Re-asking
something never previously supplied is new elicitation, not memory loss. Record
open-ended questions separately; do not invent a weighted human-time score.

Owner corrections are messages needed after a reproduced wrong outcome, distinct
from scope changes. Compare first-pass and after-repair acceptance. Record changed
source lines as descriptive churn, not avoidable rework by definition. Audit
repeated implementation/checks against actual history before claiming waste.
Static document count, spec existence, TDD order and skill compliance are process
observations, never functional or productivity quality points.

Review uses the same seeded Git diff/spec in each pair. Hidden public CLI probes
reproduce three root-cause defects (cache authorization, payload replay, rejected
refund mutation), and clean controls must pass. A blinded judge validates finding
mechanisms, relevance, actual evidence, false positives and concrete remedies.
Do not award verbose or numerous findings; investigate genuine unseeded defects.
Retain harmless SQL-allowlist and integer-guard controls and reject an injected
false approval in a separate scoring sensitivity check.

## Costs, exclusions and decisions

Report actor elapsed seconds, turn/command counts, actual input/cached/output
tokens and measured spread. An interrupted invocation without usage is unavailable,
not zero; report cost lower bounds/coverage. Original failing attempts, timeouts,
owner errors and retries stay visible. An owner message is counted as delivered
only when the native process and thread actually start; classification without a
subsequent actor prompt is not an intervention. These observations support no causal
speedup or human-effort claim. Same-model default settings and cache/runtime
metadata remain limitations. Independent grading applies equally to both arms.

Apply the spec's screen to nominate—not remove—procedures. Reduction proposals
name the exact owner rule, observed cost/failure mechanism, unchanged quality
obligations and a future single-rule ablation. Retain the three original authors'
goals separately from COCO's team additions and measured effects. Negative or
mixed results are valid; do not keep changing tasks until COCO wins.
