# coco-whattosay 적용 기록

선택한 스킬에 붙일 요청문을 추천하는 [새 스킬](../../../skills/coco-whattosay/SKILL.md)을 만들었다. 사용자가 확정한 이름은 `coco-whattosay`이며, 기본 흐름은 맥락 확인 → 전체 호출문 추천 → 선택 대기 → 선택한 요청 실행이다. 문장만 요청한 경우에는 후속 선택·수정에도 그 의도를 유지한다. 팀 신규 절차이므로 고정 원문과 131개 원본 대응은 변경하지 않았다.

## 대상과 방법

기능 브랜치는 `feat/coco-whattosay`, 시작 커밋은 `47cfe8e`, 시작 시 사용자 변경은 없었다. 기능 커밋 `0db4afefadefa5fd166134077674495cb23a0976`의 설치 파일 84개가 평가 스냅샷과 일치한다. [snapshot.json](snapshot.json)에 파일별 해시를 기록했다.

`skill-creator`의 독립 적용 절차에 따라 작성자의 대화를 상속하지 않은 두 에이전트가 각각 한 대화를 진행했다. 실제 사용자 입력은 [requests.json](requests.json)에 보존했다. 각 턴은 해당 메시지만 전달하고 응답을 받은 뒤 다음 메시지를 전달했다. 기대 답안·결함 진단·뒤의 사용자 메시지는 미리 주지 않았다.

모의 제품 자료는 작성자가 준비했고, 에이전트는 스킬과 작업 자료를 읽어 응답·명령 기록을 남겼다. 작성자는 그 응답과 명령 결과를 검토하고 원본 파일·Git 상태의 전후 일치를 별도로 확인했다. 두 에이전트는 이 저장소나 실제 설치 폴더를 수정하지 않았다.

## 패키지와 실제 설치

[검사 기록](checks.json)에는 다음 실행 결과가 있다.

- `python3 scripts/validate.py`: 26개 스킬, 고정 원문 체크섬·원본 대응·참조 통과.
- `python3 -m unittest discover -s tests -v`: 기존 23개 자동 검사 통과.
- 공식 `skill-creator/scripts/quick_validate.py skills/coco-whattosay`: 통과. 기본 Python에 PyYAML이 없어 기존 임시 작성용 가상환경을 사용했다. 패키지의 런타임 의존성은 추가하지 않았다.
- 설치 사전 검사와 `git diff --check`: 통과.

[설치 확인](installation.json)은 기존 `~/.codex/skills`에 26개 스킬·84개 파일을 설치하고, 모든 설치 파일의 원본 바이트 일치와 기존 다른 항목 71개의 보존을 확인한 결과다. 설치 후 참조 검사가 통과했고 재실행 사전 검사는 `unchanged`를 반환했다.

## 재현 자료와 범위

`review-repo/`와 `draft-repo/`에는 사용한 작업 파일을 보존했다. 리뷰의 Git 이력은 [baseline bundle](review-baseline.bundle), 변경 상태는 [스테이징 patch](review-staged.patch)와 [미스테이징 patch](review-unstaged.patch)에 있다. 새 테스트 파일은 `review-repo/tests/test_bulk.py`에 보존했다. 중첩 `.git`과 개인 설치 파일 목록·내용은 넣지 않았다. [export.json](export.json)은 보존 파일의 해시를 기록한다.

응답과 명령 기록의 절대 임시 경로는 당시 실행 위치를 그대로 남겼다. 같은 상대 위치의 보존 파일을 사용해 읽을 수 있다. 스킬 본문은 기능 커밋과 스냅샷 해시로 확인할 수 있다.

선택 결과 인계는 사용자가 앞선 선택을 전달하는 입력으로 확인했다. 현재 패키지에는 `coco-whichskill`이 없으며 실제 해당 스킬 호출을 연결한 시험은 아니다. 대상 미지정·본문 불가·네임스페이스 충돌·취소·유효한 대안이 하나뿐인 상황은 이번 독립 적용에서 실행하지 않았다. 실제 질문 UI, 전체 제품 카탈로그 조회, 외부 게시 권한, 다른 모델에서의 반복 준수도 검증 범위에 포함하지 않는다.
