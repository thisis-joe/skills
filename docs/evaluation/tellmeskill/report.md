# 제한된 적용 결과

지정된 네 항목 카탈로그를 사용해 연속 대화 6턴, 길이까지 지정한 직접 호출 1턴, 미등록 대상 선택 2턴의 실제 생성 응답 9개를 [transcript.md](/tmp/coco-tellmeskill-validation/transcript.md)에 저장하고 검토했다. 기계 판독본은 [transcript.json](/tmp/coco-tellmeskill-validation/transcript.json), 관찰·제약은 [results.json](/tmp/coco-tellmeskill-validation/results.json)에 있다.

- 최초 목록은 `coco-build` → `coco-security` → `coco-tellmeskill` → `skill-creator`로 정렬됐고 네 항목을 모두 포함했다. 대상 선택 전에는 길이를 묻거나 개별 설명을 시작하지 않았다.
- `coco-security` 선택 뒤 길이를 기다렸고, 간단 설명 뒤의 `상세로`는 같은 대상에 적용했다. `coco-build`로 바뀐 뒤에는 길이를 다시 물었다. 이전 번호와 이름의 대응도 유지됐다.
- 네 설명 응답은 같은 제목 형식과 여덟 항목의 이름·순서를 유지했다. 간단 설명은 항목별 한 줄이고, 상세 설명은 절차·분기·종료·증거·권한 조건을 확장했다. 대상 스킬의 산출물 형식으로 대체하지 않았다.
- 직접 지정한 `skill-creator 간단 설명`은 선택 단계를 건너뛰었다. `coco-unknown`은 선택 단계에 머물렀고 임의의 대상을 설명하지 않았다.
- 내용도 읽은 원문과 대조했다. 보안의 특수 모드와 Git 차단 설정, build의 동시 실행 등 조건부 동작을 조건부로 설명했고, 수행하지 않은 검증이나 실행 결과를 만들지 않았다. 사용 예는 텍스트로만 제시했다.

이 기록에서 단계 전환 오류는 관찰하지 않았다. 다만 진입점 2절의 “번호와 정확한 이름을 모두 받는다.”는 두 값을 함께 제출해야 한다는 뜻으로도 읽힌다. 1절의 “번호나 스킬 이름”과 뒤의 이름만 받는 예시와는 표현이 맞지 않는다. 이번 적용에서는 둘 중 하나를 허용하는 뜻으로 해석해 이름만으로 선택했다. 이는 확인한 문구의 모호성이며, 이번 응답에서 실제 선택 실패가 발생했다는 뜻은 아니다.

읽은 파일 9개의 경로·크기·SHA-256을 [source-hashes.json](/tmp/coco-tellmeskill-validation/source-hashes.json)에 기록했다. 진입점 해시는 `90989437a07664b8e9b72a82cf93a03757eb527f17f9acd36886d4db351f5237`, 공통 양식 해시는 `b33bb7483013a396d1c17b6142f94c82f9c27635172a25756b67dda3d268b73e`다.

이는 한 에이전트의 한 번의 제한된 적용과 생성 결과 검토다. 반복 시행·통제 비교·미래 모델 신뢰도 검증이 아니다. 실제 대화 도구의 상태 보존, 카탈로그 자동 탐색, 숫자 선택·이름 충돌·네임스페이스 중복·원문 접근 실패·취소·긴 목록은 시험하지 않았다. 원문 스킬의 실제 실행·설치·설정 변경·보안 검사·제품 구현·커밋도 수행하지 않았다. 실제 사용자 질문·외부 서비스 호출·추가 에이전트 생성 없이 임시 경로에만 파일을 썼다.
