# 검증 범위와 근거

현재 이름은 `coco-`입니다. 아래 보존 평가의 이전 이름·경로·해시는 당시 기록이며 원문 그대로 유지합니다. 접두사 변경 후의 형식·참조·실제 설치 확인은 [이름 변경 기록](coco-rename.json)을 확인합니다.

The [dual-runtime evaluation](dual-runtime/README.md) records additive Codex and
Claude Code support, actual installation in both personal destinations, preserved
unrelated files, regression checks, and native-client verification limits.

추가한 `coco-tellmeskill`의 전체 목록·단계별 선택·공통 8항목 설명에 대한 제한된 적용은 [별도 기록](tellmeskill/README.md)에 보존합니다. 현재 패키지는 안내·동기화/푸시·팀 맞춤 유지보수·요청문 추천·질의응답 학습 스킬을 포함한 27개입니다.

`coco-push`의 [로컬 Git 적용 5사례](push/README.md)에서는 실제 충돌·동시 푸시 거절 후 재통합·기준 선택 대기·사용자 변경 보존·필수 검사 실패 시 미게시를 확인했습니다. 실제 서비스의 보호 정책이나 모든 충돌 해결을 인증한 것은 아닙니다.

이후 추가한 브랜치·Jira 작업요약 정리는 [별도 적용 5사례](push-summary/README.md)에 보존합니다. 실제 로컬 Git에서는 이름 변경·기존 이름 유지로 2개를 게시했고, 모의 Jira 쓰기 거절·티켓 모호성·이름 충돌 3개는 게시 전에 멈췄습니다. Jira는 파일 기반 모의 자료이며 실제 서비스 쓰기를 검증한 것은 아닙니다.

`coco-updateskill`의 [팀 유지보수 적용 3사례](updateskill/README.md)는 원본·공통 규칙·출처를 함께 수정하는 경로, 제안 전용 요청, 개인 수정본 때문에 설치를 차단하는 경로를 기록합니다. 원본 수정과 실제 설치 결과를 구분했습니다.

이후 시작 절차를 전체 목록·대상 선택·수정 내용 질문으로 분리했습니다. [시작 대화 점검](updateskill-selection.md)은 작성자의 단계별 검토와 실행한 패키지 검사를 구분합니다. 파일을 바꾸는 업데이트를 전용 브랜치·워크트리로 강제한 뒤의 [새 컨텍스트 적용 3사례](updateskill-worktree/README.md)는 시작 체크아웃 보존, 제안 전용 요청의 무변경, Git 원본이 아닐 때의 수정 전 중단을 기록합니다.

`coco-whattosay`의 [독립 적용 2대화·7턴](whattosay/README.md)은 확정한 스킬의 요청문 추천과 선택 대기, 번호 선택 후 실제 리뷰, 문장 전용 상태의 수정·유효하지 않은 번호 처리, 명시적 실행 요청 후 결과 생성을 확인합니다. 임시 제품 파일·Git 상태의 보존과 실제 26개 스킬 설치도 기록합니다. `coco-whichskill` 자체의 실행 연동을 시험한 것은 아닙니다.

`coco-askme`의 [독립 적용 3대화·15턴](askme/README.md)은 전체 작업 후보 제시, 부분 복수 선택, 대상 사전 지정, 모르는 답변, 사용자 역질문, 설계 대안 인정, 성능 근거 부족, 도중 범위 변경을 확인합니다. 대상 저장소의 상태 보존도 기록합니다.

`coco-build`의 [Jira 브랜치 규칙 확인](build-branches.md)은 한글·괄호가 있는 이름의 실제 생성, 유효하지 않은 후보와 중복 이름의 Git 거절, 사용자 파일 보존을 기록합니다. Jira 조회나 에이전트의 질문 행동을 실행 검증한 것은 아닙니다.

이 모음은 스킬 문서와 공통 계약을 통해 에이전트의 판단을 안내합니다. 형식 검사나 한 번의 에이전트 시나리오 통과가 모든 모델·제품·프로젝트에서의 준수를 보장하지는 않습니다.

## 기준선

[baseline.md](baseline.md)는 원본 규칙을 적용한 12개 상황과 5개 추가 검토를 기록합니다. 원본의 정적 변경 예외·기존 승인 재사용·dirty work 보호처럼 이미 올바른 동작은 실패로 계산하지 않았습니다. 확인한 연결 문제는 미커밋 코드 리뷰 범위, 리팩터링 시점, 커밋 후 상태 갱신 중단, 넓은 마이그레이션의 중간 상태입니다.

기준선은 원문을 읽은 한 에이전트의 근거 있는 시뮬레이션입니다. 원본 팩을 실제 각 제품에 설치한 대조 실험이나 독립 모델 5회의 측정으로 해석하지 않습니다.

## 자동화된 기능 검사

`python3 -m unittest discover -s tests -v`는 임시 실제 Git 저장소에서 리뷰 범위를 검증하고, 임시 스킬 폴더에서 설치 충돌·업데이트·참조·체크섬을 검증합니다. 원본과 통합 문장을 문자열로 맞추는 테스트가 아닙니다.

`python3 scripts/validate.py`는 고정 원문 체크섬, 131개 원본 항목의 대응, 현재 27개 스킬의 형식·UI 이름·참조를 검사합니다. 이것은 의미와 행동의 완전한 증명이 아닙니다.

최초 통합 시 자동 테스트 23개가 통과했습니다. [당시 공식 스킬 형식 검사](format-validation.json)는 진입점 22개 모두 통과했습니다. [당시 활성 파일 해시](final-bundle.json)는 재개 평가와 조건부 평가의 고정 대상과 일치하는 72개 설치 파일을 기록합니다.

## 새 컨텍스트에서의 동작 평가

작성자의 대화와 기대 답안을 전달하지 않은 새 컨텍스트에서 적용했습니다. 각 평가의 한 에이전트가 여러 시나리오와 작은 fixture를 작성·적용했으므로, 독립 모델 반복 실험이나 맹검 효과 측정으로 해석하지 않습니다.

| 평가 | 관찰한 결과 | 제한 |
|---|---|---|
| [핵심 절차 12개](core/report.md) | 시나리오 행동 11개 통과, 재개 담당 1개 불명확. 실제 red→green·작업별 커밋·사용자 dirty 변경 보존·새 파일 리뷰 확인 | 평가 중 읽은 파일 5개 변경. 모든 경우가 하나의 고정 버전으로 통과했다고 주장하지 않음 |
| [전문 절차 12개](specialist/report.md) | 제한된 적용 9개 통과, 제품 산출물 3개 미확인. 로컬 fixture 검사 15개 통과 | 실제 브라우저·형식 증명·실행 도우미의 필수 근거 없음. 결함 재현 검사 통과는 해당 제품이 안전하다는 뜻이 아님 |
| [수정 후 재개 2개](recovery/report.md) | 고정 파일로 구현 재개와 맥락 확인 전용을 구분. 기존 커밋 재사용, build만 완료 상태 갱신 | 이 fixture에는 보존할 별도 dirty 변경이 없었음. 실제 독립 코드 리뷰를 수행한 것은 아님 |
| [조건부 절차 8개](conditional/report.md) | 명령 가드·fixture 전환·커밋 훅·마법사·정리 계획·PR 확인·명세 전용·품질 기준의 구체적 산출물 | 합성 제품 자료와 도구 미설치 제한을 각 사례에 기록. 실제 호스트 훅·외부 PR·서비스 설정 성공으로 확대하지 않음 |

핵심 평가의 재개 담당 문제는 수정 후 별도 고정 파일 평가로 확인했습니다. 이전 보고서의 불명확 판정과 파일 변경 기록은 그대로 보존했습니다. [리뷰 원문](final-review.md)과 [수정 근거](review-resolution.md)도 함께 남겼습니다.

## 보존 자료 읽기

각 하위 폴더의 `report.md`, `results.json`, 입력·산출물·명령 기록을 먼저 읽습니다. 보고서의 절대 `/tmp/…` 경로는 당시 실행 위치입니다. 상대 경로가 같은 보존 사본을 이 디렉터리에 두었으며 `export.json`에 해시와 제외 항목을 기록했습니다. 원본 보고서나 명령 출력을 사후에 고쳐 쓰지 않았습니다.

Git 저장소 내부는 중첩 `.git`으로 넣지 않고 각 평가 폴더의 `git-history/`에 bundle로 보존했습니다. 사본에서 검사를 다시 실행하려면 필요한 이력을 별도 임시 폴더로 복원하고 당시 절대 경로를 조정해야 합니다. 평가 스크립트는 설치 대상에 포함하지 않습니다.

조건부 평가 초반 npm 명령 하나는 기본 로그 위치를 사용했습니다. 따라서 임시 폴더 밖의 진단 로그 생성 가능성을 배제하지 못하며, 이후 명령만 임시 npm 경로를 사용했습니다. 사용자 전역 설정 변경·패키지 설치·실제 외부 훅 활성화를 수행했다는 의미는 아닙니다.

원본 팩을 각 제품에 설치한 대조 실험, 생산 환경, 실제 배포, 모든 모델·브라우저 제품의 검증은 수행하지 않았습니다. [완료 점검](completion-audit.md)과 [실제 설치 기록](installation.json)은 이번 통합·설치의 범위를 확인하는 근거입니다.
