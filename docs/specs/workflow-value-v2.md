# Workflow value v2 evaluation

## Purpose

Evaluate whether COCO makes the agreed development procedure clear and consistent,
supports pickup by another worker, and makes choosing help simple. Compare frozen
COCO `622975e`, actual published `0.2.0`, and no loaded skill bodies separately.
Preserve the original report and failures. Do not change active skills to win.

The reader is the team deciding how to use COCO. Procedure agreement, decision
ownership, usable work records and a reproducible completion boundary are valid
outcomes, even when functional output is equal. Their existence alone is not
proof of human usability or productivity. Keep observations and hypotheses apart.

## Required observable outcomes

1. A worker can explain what is agreed, what is implemented, what remains, and
   the next permitted action without contradicting the actual project.
2. Repeated workers preserve the same agreed scope and completion boundary;
   do not substitute procedure names or document counts for this consistency.
3. A new native context without the writer's conversation can recover decisions
   from actual surviving artifacts, finish the remaining public CLI behavior and
   preserve completed behavior. Missing facts must remain unknown, not invented.
4. A newcomer gets an actionable, understandable recommendation for their purpose
   without needing to learn the complete catalog. No-skills may recommend an
   equivalent concrete action; exact COCO names are not required for fairness.
5. Each condition has five matched handoff samples and five matched selection
   cases, with raw native actions and independent, condition-label-blinded judgments.
6. Report each axis and pairwise comparison, costs and limits; retain adverse and
   unavailable outcomes. No claim of actual human comprehension without humans.

## Boundaries

Five purchasing-catalog handoffs vary settled SKU/duplicate/error/summary policy.
The first worker receives those decisions in its conversation, implements import
and stops before summary. It may choose its own surviving records. The successor
gets only the real repository, generic continuation and common tool authority.
No experimenter memory packet is injected. The public contract is identical;
the exact policies must be preserved from the first worker's own work.

Five selection contexts cover an unsettled feature, a ready implementation,
unexpected failure, review of committed work, and verification blocked by missing
runtime. Selection is advice only, with no product edits. Cold manual discovery
is separate from the explicitly automatic implementation/handoff profile.

Use existing native recording and CLI observers where adequate. Existing ongoing
two-arm ambiguity/change/restart trials are supplemental, not a replacement for
the new three-arm test, and must retain their frozen protocol and identities.

No global installs, source-policy edits, publication or fabricated human sessions.
Produce `docs/evaluation/staged-development/report-v2.md`, the protocol, raw
evidence, results and independently reconciled review. Commit work units on
`experiment/coco-workflow-v2`; preserve the existing checkout and branches.
