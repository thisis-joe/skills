# Collaboration value evaluation

## Objective and non-goals

Compare frozen COCO `622975e` with no loaded skill bodies on ambiguity, changing
requirements, lost conversational context, and review of real reachable defects.
Measure incremental outcomes and costs, not compliance with COCO's own process.
Preserve the earlier null findings. Do not infer effectiveness of the three
original upstream trees, which this experiment does not execute.

Produce an inspectable report and an evidence-based procedure-reduction plan.
Do not change active skill policy, install globally, push, or deploy in this work.
Any removal needs a later isolated ablation and must respect settled user choices.

## Conditions and units

Five paired independent lifecycle projects run ambiguity -> requirement change
-> interruption -> fresh-context resumption. These are five longitudinal samples
per arm, not fifteen independent observations. A separate five-pair review set
uses identical seeded changes in both arms. Total: ten lifecycle projects and ten
review projects. Order alternates within matched pairs; no variant labels, private
facts, rubric, source archives, or expected winners appear in project paths.

Same native default model, settings, local tools and permissions in both arms.
All shared task-level authorizations are given initially, not only to the arm
that asks a question. Basic automatic execution is explicitly authorized for this
feature; product decisions remain with the owner. Same-agent inspection is an
accepted limitation inside lifecycle sessions; a separate review set measures
fresh review on exactly the same code. No nested agents, packages or publication.
Record preexisting runtime catalog metadata and audit actual skill-body reads.

COCO receives the complete frozen active `skills/` snapshot as local `.guide`;
bare has none. No special idealized instructions replace either arm. Source
audits use upstream `.source` files only as inert evidence, never executed policy.

## Lifecycle project

A Python stdlib inventory CLI currently lists a persisted catalog. The owner
wants CSV import and a purchasing summary, with a runnable import slice first.
Initial natural brief leaves four real business choices unsettled: SKU identity,
duplicate collisions, malformed-row atomicity, and whether summary includes
zero-price entries. Five fixed owner profiles vary those choices. They are kept
outside the project and disclosed only in response to relevant actual questions;
an open-ended requirements question may legitimately elicit several facts.

The semantic synthetic owner answers from a frozen fact sheet, retains the
history of facts already supplied and never grants new blanket authority. It
does not see the arm label. Retain its actual prompts/actions/replies and code
its factual accuracy separately from candidate performance. An identical maximum
of four interactive replies per phase prevents unlimited rescue. Human active
time, comprehension and satisfaction remain unmeasured; intervention measures
are labeled synthetic proxies.

The first import milestone is public CLI execution on valid unique rows, not
spec creation, a skill handoff, a final-answer keyword or document count. After
that milestone, check actual chosen behavior. Reveal concrete owner corrections
only for unmet owner decisions, count them separately and allow the same bounded
repair opportunity. Keep first failures and later results.

Then the owner changes scope: multiple suppliers require composite identity,
old data belongs to `legacy`, explicit batch IDs must be idempotent, changed
payload under the same supplier/batch ID must fail without state changes, and
old invocation remains usable. The import/storage change is committed before
the remaining summary work. This is one common external work-unit checkpoint.

At the actual committed runnable changed-import checkpoint, finish the current
native turn, retain its files/state and discard the conversation. A new process/new native thread gets the same generic resume
request and only the project's actual surviving files. Do not use native thread
`resume` for this boundary or inject an experimenter-authored memory summary.
This is a planned work checkpoint with actual conversation loss. A pre-primary
host probe could not establish reliable tool-child cancellation after SIGTERM;
abrupt process interruption is therefore unavailable, not silently simulated. The new
agent completes summary under the previously agreed choices and preserves the
changed import behavior. Lost facts may be requested again; count those requests.

Checks use real public CLI calls, SQLite files across processes, no-loss/error
paths, changed behavior, original invocation and final summary values. A common
unrelated file must remain unchanged and uncommitted. Extra documents/tests are
not quality points. Churn required by the legitimate change is not automatically
waste: distinguish owner correction, regressions and unnecessary repeated work
from descriptive source churn.

## Independent review project

Both arms receive exactly the same proposed billing/refund patch, spec, project
rules and Git base. Actual reachable seeded defects include a warmed cache that
bypasses tenant authorization, idempotency that ignores the request payload, and
rejected over-refunds that mutate stored state. A correct allowlisted SQL ordering
pattern and valid integer guards are harmless distractors, not required findings.

First prove each defect through public execution in an isolated database and
prove the repaired control satisfies those checks. Reviewer runs are read-only;
no author rationale, seeded-bug identities or expected number of findings. Judge
reports blind to condition using a frozen scale: confirmed defect recall,
reachable severity/impact, false positives, actionable evidence and unsupported
approval. A genuine additional in-scope defect is investigated and scored in both
arms, never automatically marked false because absent from the seed list.

## Metrics and interpretation

Report per pair, per stage and overall, with median/range for five samples:

- Quality: public acceptance pass/fail, data preservation, original behavior,
  false completion, confirmed review defects, false positives.
- Synthetic intervention: product decisions elicited, generic fact elicitation,
  owner correction messages, settled-fact re-questions, procedural authorization
  questions, scheduled events. Scheduled events are common inputs, not avoidable
  intervention. Question count alone is not the burden score.
- Rework: wrong-assumption correction, regressions repaired after change/resume,
  duplicate implementation or repeated valid checks; source churn is descriptive.
- Cost: actor seconds, actual turns, command counts, input/cached/output tokens,
  errors/timeouts/retries. Report synthetic-owner and grading costs separately.

No population, causal speedup, human ease or upstream-tree superiority claim.
Five pairs are a bounded operational screen, not proof of statistical equivalence.
Freeze budgets, fixtures, owner facts, scoring and source hashes before primary
runs. Preserve all failures and targeted repairs. Never replace an unfavorable
initial outcome with a successful rerun without labeling it.

## Procedure-reduction plan criteria

If COCO costs more in at least four of five pairs and improves none of quality,
owner corrections or avoidable rework in that family, nominate excess procedures
for a focused ablation. A two-arm comparison cannot identify a particular rule's
causal effect. Keep source unchanged at screening. A future five-pair single-rule
ablation may justify removal if it adds no acceptance failures, severe defect
misses or owner corrections and reduces median actor cost by at least 20%.
These are explicit operating gates, not statistical or universally optimal claims.
Mixed/quality-sensitive results call for targeted redesign, not blanket removal.
