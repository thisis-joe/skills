# 기능 보존을 우선한 조건부 문서 로딩

## 변경 이유와 범위

COCO는 Matt Pocock, Addy Osmani, Lauren Tan(pstack)의 원본 기능을 COCO 호출만으로 사용할 수 있게 통합한다. 이 개선은 사용자가 원본 명령이나 내부 모드 이름을 더 외우지 않으면서, 필요한 지침만 읽게 하는 구조 변경이다. 판단 품질과 기능 보존을 컨텍스트 절약보다 우선한다.

기준 버전은 `1f0f37012ae37f65697872fa97276860a3a7e82f`다. 당시에도 고급 문서는 조건부였다. 개선 대상은 그 고급 파일 하나 안에 서로 다른 전문 절차까지 묶여 있던 부분이다. 전체 설치 크기나 파일 개수를 줄이는 변경은 아니다.

## 유지한 계약

- 26개 스킬의 호출 이름, 발견용 `name`·`description`, UI 메타데이터와 `_coco-shared/contracts.md`는 유지한다.
- `verify.md`의 기존 11개 절과 `automate.md`의 기존 12개 절, 두 서문을 바이트 그대로 보존한다. 원문 23개 절을 삭제하거나 요약하지 않는다.
- 권한, 사용자 변경 보존, 검증 근거, 실패/미확인 구분, 작업 소유권, 완료·중단·재개 기준은 계속 적용한다.
- 고정 원문 `.source`, manifest 체크섬, 원본 `essential_rules`와 채택 이유를 바꾸지 않는다. 새 위치는 coverage의 구현 참조와 원본 대응 안내에 반영한다.
- 일반 앱/API/CLI 검증은 전문 모드가 필요하지 않으면 기존 진입점과 공통 계약만으로 진행할 수 있다. 두 진입점에 짧은 트리거 점검 문장이 추가되어 기본 텍스트 분량 자체는 조금 늘어난다.

## 로딩 구조

기존 `advanced/verify.md`·`automate.md`는 서문, 필수 4개 절, 누적 선택표를 가진다. 나머지 15개 절은 같은 디렉터리의 별도 문서로 옮겨 기존 상대 링크를 보존한다.

| 계열 | 공통으로 남긴 절 | 조건부 문서 |
|---|---|---|
| verify | claim, behavioral checks, runtime journey, return evidence | quality audit, runtime create/maintain, formal create/maintain, workflow experiments, pre-commit setup |
| automate | operation, retry/crash, decision trail, return | CI, sustained tasks, webhook, intake setup/triage/fix, manual wizard, workflow specification |

각 모듈의 짧은 서문은 직접 진입한 경우에도 해당 공통 절차와 선택표를 먼저 적용하게 한다. 기존 운영 절의 해시에는 이 새 서문을 포함하지 않는다. 사용자가 선택하는 진입점은 계속 `coco-verify`·`coco-automate`다.

선택 조건은 독립적으로 모두 점검하며 동시에 여러 모드를 적용할 수 있다. 처음과 범위·위험·상태·전제조건이 바뀔 때 다시 점검하고, 관련 행동 전에 필요한 문서를 읽는다. 불확실하면 관련 범위를 넓게 읽고, 분류할 수 없으면 모든 모드를 읽는다. 필수 문서를 읽을 수 없으면 해당 문서에 의존하는 행동을 중단한다.

runtime/formal 유지 작업은 생성 절차의 계약도 함께 읽는다. intake triage는 setup을, intake fix는 setup·triage를 선행 읽는다. 추가 로딩은 생성·변경·외부 쓰기 권한을 넓히지 않는다. 명세만 요청한 경우 실행 모드를 함께 읽어도 결과는 명세로 끝낸다.

## 의도적으로 채택하지 않은 최적화

공통 안전 규칙 축약, 발견용 설명의 공격적인 단축, 원본 기능 제거, 무조건적인 재읽기 금지는 이번 범위에 넣지 않는다. 특히 "이미 읽었다"는 기록이나 파일 해시는 맥락 압축 뒤에도 내용이 남아 있다는 증거가 아니다.

분류가 불확실해서 모든 모드를 읽는 경우에는 선택표와 모듈 서문 때문에 종전보다 더 길어진다. 이는 기능 누락을 피하기 위한 보수적 비용이다. 모든 요청의 토큰·시간이 감소한다고 주장하지 않는다.

## 보존과 행동 검증

`tests/fixtures/context_loading_baseline.json`은 기준 버전의 서문과 원래 순서·제목·본문 SHA-256을 기록한다. `tests/test_context_loading.py`는 원래 23개 절의 단일 소유, 배치·순서, 정확한 재조합 해시, 선택표에서 모듈로 가는 링크, 직접 진입의 공통 절차 링크, 상대 참조를 검사한다. 임시 복사본에 누락·변조·중복·링크 손상을 주입해 검출되는지도 확인한다.

원래 절 사이 구분 빈줄까지 보존하면서 공통 문서의 마지막 절이 되었으므로 분할한 15개 파일에는 빈 EOF 줄이 남는다. `git diff --cached --check`의 해당 15개 경고는 기록하며, 이를 숨기기 위해 검사 설정이나 원문 해시를 바꾸지 않는다.

패키지·출처 검증과 자동 테스트는 의미와 행동의 완전한 증명이 아니다. [별도 적용 기록](evaluation/context-loading/README.md)에서 고정한 현행본/후보본을 별도 맥락에서 같은 로컬 입력으로 적용한 관찰, 실제 파일 분량, 검증 범위와 한계를 확인한다. 권한·사용자 변경·허위 완료 등의 새 회귀가 발견되면 절약과 관계없이 채택을 중단하고 해당 변경을 수정하거나 되돌린다.
